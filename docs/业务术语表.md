# 两人吃饭网站业务术语表

本文件记录两个人使用网站选菜时已经确认的说法。

## 业务用词

**共享冰箱**：两个人在各自手机上查看和修改同一份已有食材。

**共享采购清单**：两个人在各自手机上查看和修改同一份需要购买的食材清单。

**主要食材已齐**：一道菜需要的主要食材都已记在共享冰箱中，不表示重量足够，也不表示常用调料齐全。

**想吃分数**：一个人对一道候选菜想吃的程度，最低 0 分，最高 5 分。

**合计分数**：两个人给同一道菜的想吃分数之和，最高 10 分。没有评分不能当成 0 分。

**入选菜**：两个人都完成评分，且合计分数大于等于 7 分的菜。

**未入选菜**：两个人都完成评分，且合计分数小于 7 分的菜。结果公开后记入本轮淘汰记录，自动换成另一道同类菜；没有可换菜时保留该结果和原因。

**不再推荐**：菜品仍留在菜单里，但不参加日常推荐；之后可以恢复推荐。

**永久删除菜品**：从可管理的菜单中移除一道菜，不能通过恢复推荐找回。历史晚餐保留当时菜名、食材和评分。

**共同口令（旧版）**：旧版两个人约定的厨房入口口令；相同口令定位同一份厨房数据。微信登录新版关闭此旧入口。

**评分身份**：获准加入厨房的成员进入时选择“男生”或“女生”，本次仍允许切换，不绑定固定微信账号。加入审批不验证现实中的情侣关系。

**食材分类**：在冰箱中按蔬菜、肉类等分组，方便找食材。它不是晚餐菜品的荤素分类，例如鸡蛋可以单独归入“蛋类”，不因此改变一荤两素的搭配规则。

**待选食材**：在添加面板中已经勾选、但还没有保存到共享冰箱的食材。切换分类不会清空，关闭面板会丢弃，点击“加入冰箱”成功后才供两个人共同查看。

**评分公开**：同一道菜两个人都完成评分后，两个人才能看到对方的具体分数。此前各自只看自己的分数，以及对方是否已经评分；出结果后不能修改该道菜分数。

**本轮淘汰菜**：本轮两个人评完后合计低于7分的菜，保留菜名和两个人的最终评分，本轮随机和自选都不再选它。新一轮会重新允许推荐，不等于菜单里的“不再推荐”。

**搭配数量**：每顿分别选择荤菜和素菜道数，默认一荤两素。开始本轮后数量固定；页面里后续调整的数字用于下一轮。

**历史晚餐**：当前轮之前保存的选菜和评分记录。它记录怎么选，不证明已经做饭或吃饭。保留最近30轮，包含当前轮。

**再吃这一顿（已取消）**：早期历史页面的复用入口，三餐日历不再提供此操作。

**三餐日历**：按日期查看已完成双人评分菜品的独立栏目，不区分早餐、午餐和晚餐。同一天的多轮记录按最新到最早展示，每轮只展示已完成双人评分的菜品；没有此类菜品的轮次不展示。这些记录不证明实际已经做饭或吃饭。

**长期日历记录**：每道菜完成双人评分后保存的当时菜名、食材和分数，单独保留，不随最近30轮选菜数据的清理而删除。

## 微信账号与厨房权限（2026年10月10日确认，新代码待发布）

**微信账号身份**：由后台核实的当前微信用户身份，用于区分不同用户，不以页面自报的身份信息为准。

**我的厨房**：当前微信账号已经获准加入的厨房列表。申请中的厨房不算已经加入的厨房，旧系统未记录微信身份的访问无法自动还原。

**厨房加入申请**：非成员输入口令后请求加入厨房，创建者同意之前不能查看厨房内容。

**厨房数量白名单**：由后台管理的微信账号名单，名单里的用户不受拥有厨房数量上限和每天创建次数上限限制。白名单不授予访问其他厨房的权限。

**拥有厨房数量**：数量上限只计算当前微信账号自己创建的厨房，受邀加入别人创建的厨房不占名额。普通账号上限为三个，厨房数量白名单账号免除该上限。

**白名单更新生效时间**：名单保存到数据库后，处理修改的后台实例清除对应账号缓存；其他实例最多继续使用旧名单60秒。过期后的权限检查须重新读取数据库，读取失败时不继续使用过期权限。已通过权限检查的在途请求可能继续完成。

**加入口令**：新厨房由系统生成的随机口令，非成员用它申请加入，创建者同意之前不能读取厨房内容。输入不存在的口令不创建厨房。

**管理员**：由后台可信配置指定、可以扫码登录管理网页维护白名单的微信账号。普通白名单用户不因此获得管理员权限。
