# 微信小程序手机适配说明

## 已确认的需求

手机上减少顶部留白，让候选菜更早出现；按钮容易点中；小屏文字和操作不挤在一起。编辑菜品和自选菜弹窗需要在键盘出现后继续使用。

## 本次调整

- 保留原有配色和四个入口，缩短登录、晚餐页面的标题与说明，减少卡片间距。
- 操作按钮最小高度为44像素。320像素宽的手机将0到5分排为两行，每行三个；大屏继续一行显示。
- 长菜名和食材允许换行；小屏冰箱食材每行一项，菜单操作按钮自动换行。
- 编辑菜品和自选菜使用底部弹窗。标题、关闭按钮和保存按钮固定，中间内容可以滚动。
- 使用微信输入组件提供的键盘高度，结合当前窗口高度调整弹窗位置。已经被系统缩小的窗口不再重复向上移动。输入或打开弹窗时隐藏底部导航。
- 使用现有微信组件和页面生命周期，没有新增界面依赖。共同口令、两人评分、7分入选、一荤两素和共享接口继续沿用现有规则。

## 验证结果与边界

- 微信开发者工具中检查390像素宽的常规手机和320像素宽的小屏手机。候选菜、菜单按钮和编辑弹窗显示正常；小屏评分分两行。
- 小程序自动测试共4项通过，包括原有评分展示、登录请求、共享数据刷新，以及新增的键盘与窗口尺寸事件顺序测试。
- 新增测试覆盖窗口保持高度、窗口先缩小、键盘先通知、键盘关闭后窗口恢复，以及页面卸载后的事件。
- JavaScript语法和代码空白检查通过。
- 尚未在真实安卓和iPhone设备上验证键盘、系统大字体与横屏效果；模拟器检查不能替代真机检查。

## 使用与发布

修改已保存在桌面的“两人厨房”项目中，开发者工具已显示新布局。本次没有提交或推送GitHub，也没有上传小程序版本。

GitHub的云托管自动发布用于后台服务，不会自动更新微信客户端的小程序页面。需要在开发者工具上传新版本，再设置体验版或提交微信审核；发布前请用两部手机检查编辑菜品时的键盘和保存按钮。


## 2026年10月10日：五页功能重点与排版调整

### 已确认的范围

用户确认一起调整选菜、冰箱、采购清单、菜单和三餐日历，删除重复和次要提示，统一组件大小。补充要求是继续压缩日历高度。已有评分、共享、菜品管理和长期记录规则保持原样；本次不提交代码、不上传微信版本。

### 设计取舍

沿用现有绿色，按钮和选中日期使用深绿 `#3c5944`，页面底色 `#f7f5ef`，内容底色 `#fffefa`，文字 `#28382d`，次要文字 `#74816a`，分隔线 `#e2e5da`。采用系统中文字体，避免加载额外字体影响小程序打开速度。页面标题42rpx、菜名38rpx、正文约27～30rpx、辅助文字25rpx；小屏标题缩小。每页左对齐，主要按钮突出，菜单的编辑、停用和删除作为次要操作。

选菜页按“搭配条件 → 候选菜 → 评分 → 采购”排列，不增加展示图片和动画。冰箱继续采用左侧分类、右侧食材；日历继续显示完整月份，不改成仅显示一周，避免增加查找日期的步骤。

### 已实现的调整

- 登录页减少重复介绍，保留同一口令进入同一厨房、口令不同会打开另一厨房以及可切换身份的说明。
- 选菜数量、冰箱限制和搭配按钮集中展示；菜卡首先显示菜名和状态。评分公开和7分规则只在候选区说明一次，删除每张卡重复的规则文字。
- 冰箱收窄分类侧栏，统一食材行高，突出搜索、添加和管理，保留左滑移除提示。
- 采购页突出食材清单和“加入冰箱”的已买数量，保留加入后从清单移除的说明。
- 菜单使用连续列表，减少大卡片留白；次要操作使用较小文字，但仍保留至少44像素的点击高度。
- 日历去除装饰标题和底部圆点说明，缩短月份栏、周标题、日期行和卡片边距。日期格高度至少44像素；七列排列、日期选择和记录圆点保留。
- 添加食材面板缩短提示，分类、清空和已选食材按钮的点击高度补齐至44像素。键盘处理继续沿用原逻辑。
- 使用微信现有组件和WXSS，没有新增依赖，没有修改后台、评分方法或真实厨房记录。

### 本次验证

小程序交互测试10项通过，覆盖评分隐藏、冰箱左滑、数量草稿、键盘、日历切换和分页。微信开发者工具的390像素模拟器中检查了五页和添加食材面板，页面没有出现横向溢出或操作遮挡。日历下方仍显示已有后台版本不支持日历的提示，因此本次只验证月历布局，未验证线上日历记录。

320像素排版保留评分两行和按钮换行规则，但本次未重新完成320像素模拟器截图检查。尚未真机验证。本次未提交、推送或发布。
