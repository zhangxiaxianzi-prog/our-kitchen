# 网站与小程序共用厨房数据

## 背景

Sites网站已保存共享菜单、冰箱和晚餐。用户新增微信小程序，并提供微信云托管环境及服务。截图中自动开通的MySQL不是现有厨房数据所在位置。

## 比较过的做法

1. 给小程序另建数据库：小程序部署独立，但两个入口需要同步菜单、库存和分数，同时修改时很难保证一致。
2. 把所有数据和接口搬到微信云托管：只保留一套数据，但必须迁移原厨房、登录口令对应关系、运行密钥以及网站请求方式。
3. 小程序通过微信云托管调用原Sites接口：保留同一份数据和已有规则，增加网络转发这一步。

## 选择和理由

选择第三种。现有网站保持正常工作，不迁移已经使用的厨房，也不复制评分、配菜和保存规则。微信云托管服务只允许固定厨房接口，与网站共用同一份数据。

## 影响

两个入口依赖Sites接口和它的运行密钥，不能把云托管MySQL当作数据源。云托管与Sites之间的网络需要真机验证；后续若要整体迁移，须设计原数据和厨房编号迁移后再切换，不能简单更换服务器地址。
