# 三餐日历长期保存

## 背景

原历史放在厨房 JSON 中，每次评分和冰箱同步都读取整份数据，并只保留最近30轮。用户确认按日历长期查看已完成双人评分的菜品，随后取消网站，微信小程序为唯一入口。

## 比较过的选择

- 保持30轮：无法保证过去月份的记录仍存在，不满足长期保存。
- 移除JSON上限：每次查询冰箱和评分都随历史增长，受2MB厨房内容上限影响，不能支持长期使用。
- 独立历史表：新增按月份和日期查询，评分保存时同时归档，当前厨房保持有界。需要处理事务、旧记录补入和独立备份。

选择独立历史表，保留当前厨房最近30轮操作数据。菜品完成双人评分后归档当时内容，候选编号和轮次编号去重，后续菜单变更不改写历史。评分和历史在同一数据库事务提交，避免一边成功一边失败。

## 影响

日历详情每批40道、导出每批100道、恢复每批20道，内存不随多年历史一起增长。所有SQL为单表查询和写入，身份限定厨房。首次登录或读取日历补入微信后台仍存在的已完成记录，不恢复已删记录或旧网站数据。

现有厨房备份不能涵盖独立历史，需要另存日历备份。先发布后台，再上传小程序；本地检查不能代替真实MySQL和线上发布验证。
