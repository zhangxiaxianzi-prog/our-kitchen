# 冰箱分类管理说明

## 本次确认的操作方式

冰箱首页和“添加食材”面板都增加左侧分类栏：全部、蔬菜、肉类、禽类、水产、蛋类、豆制品、菌菇、其他。分类旁显示食材数量，左右列表可以分别滚动。食材分类只用于找食材，不改变晚餐“一荤两素”的规则。

冰箱首页先展示实际已有的食材。可以按分类或名称查找，点击“管理”后勾选多项，统一修改分类或移除；移除前展示食材名称并要求确认。平时查看时不会给每一项放置删除按钮。

点击“添加食材”打开底部面板，可以搜索常见食材、跨分类勾选，再点“加入冰箱”。切换分类和搜索不会清空待选项。清空待选项或关闭面板会丢弃当前选择，保存失败会保留面板和选择，方便重试。

不在列表中的食材可以逐个输入，选择分类后点“待选”，再统一加入冰箱。输入框中的名字尚未点“待选”时，不直接忽略该输入保存。西红柿归为番茄，马铃薯归为土豆，沿用已有名称归并规则。

每次最多处理 20 项，冰箱最多保存 200 种食材。已有食材不再出现在添加列表中。另一人添加或移除食材后，刷新会清理已经失效的勾选，避免把旧选择继续提交。

仍然只记录主要食材名称，不记录重量、保质期，也不在确定晚餐后自动扣除食材。

## 两个人如何共享分类

现有冰箱名单仍使用 pantry 字符串数组。新增可选的 pantryCategories 数组，记录手动选择的食材分类，并随厨房记录一起保存到现有数据库。没有这个字段的旧厨房和旧备份仍可以读取，无需修改数据库表。

常见食材默认分类放在小程序的统一食材清单中；手动设置的分类优先于默认分类。无法识别的食材归入“其他”，可以在管理模式中调整。移除食材时同时移除其手动分类，避免名单外残留分类。

## 批量接口

沿用 POST /api/kitchen，以及已有登录验证和厨房版本检查。新增三个 action：

- pantryAddMany：统一加入食材，可携带分类。
- pantryRemoveMany：统一移除食材。
- pantryCategorize：修改已有食材分类，每一项必须填写分类。

加入请求示例：

```json
{
  "action": "pantryAddMany",
  "items": [
    { "name": "排骨", "category": "meat" },
    { "name": "青菜", "category": "vegetables" }
  ]
}
```

移除请求的 items 只需要 name；修改分类请求的 items 需要 name 和 category。可用分类值为 vegetables、meat、poultry、seafood、eggs、soy、mushrooms、other；all 只用于页面筛选，不能保存为食材分类。

服务器先检查整批内容，再修改厨房记录。非法分类、超过数量限制或给已经移除的食材修改分类时，整批请求失败，不保存一半。两台手机同时操作时，沿用现有读取最新版本并重试的保存方式，不拿页面上的旧冰箱名单覆盖数据库。

原来的单项加入、移除接口继续保留。备份工具增加分类检查，手动分类的食材必须仍存在于冰箱中。

## 更新顺序

1. 先提交并发布微信云托管后台，等待新版本正常启动。
2. 在独立测试厨房确认批量加入、修改分类和批量移除可以保存，并检查另一台手机读取的结果。
3. 再上传包含本次修改的小程序，真机验证后按微信平台流程发布。

新小程序需要新增的批量接口；只上传小程序、后台仍是旧版本时，保存会失败。不能用逐个提交的办法替代整批保存，否则失败时会出现部分食材已经保存的情况。回退时先回退小程序页面，并保留支持新旧操作的后台。

本次没有提交、推送 GitHub 代码，也没有上传或发布微信版本。
