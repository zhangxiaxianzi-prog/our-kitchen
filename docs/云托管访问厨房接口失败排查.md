# 云托管访问厨房接口失败排查

## 已确认的现象

用户提供的日志显示，10月9日20:08:23，springboot-5wzu-002打印“两人厨房小程序接入服务已启动”；20:23至20:24多次打印“连接厨房接口失败，请检查服务网络”。这证明请求进入了接入服务并遇到上游异常，不能据此确定具体网络原因。

本次在用户电脑上只读访问Sites的/api/kitchen，不携带登录票据，返回HTTP 401、application/json及预期的未登录提示。该结果只证明电脑到网站的访问正常，不证明微信云托管容器到网站的访问正常。

## 已确认的代码问题

wechat-gateway/server.cjs中的forward将Node网络异常重新包装为统一文案，原错误编号丢失。接入服务捕获异常后又只打印固定一句话。DNS解析失败、连接超时、证书异常、响应读取失败、非JSON返回均无法从现有日志区分。

/health只检查接入服务是否启动，不检查与Sites的连接是否正常。

## 已确认并实现的排查方案

保留现有共享厨房及数据规则。使用Node已有的错误编号和HTTP响应信息，按固定字段记录失败阶段、错误编号、接口路径、耗时、HTTP状态和内容类型；日志描述使用中文，不打印口令、登录票据、请求正文或响应正文。不增加任意网址访问入口。

增加网络故障及非JSON响应的检查，确认日志能区分失败原因。用户已确认方案；已修改错误处理并生成新的服务包。需要在云托管重新部署并复现一次，按真实错误继续处理。补齐错误信息不能视为云端网络故障已修复。

## 第二次云端证据：403与HTML

用户提供10月9日21:08:23的新版本springboot-5wzu-003日志：POST /api/login，阶段为解析网站响应，324毫秒收到HTTP 403，内容类型text/html，错误编号UPSTREAM_INVALID_JSON。

由此确认该次请求收到了上游HTTP响应。403代表请求被拒绝，JSON解析错误是拒绝页返回HTML之后的结果。本机使用与容器一致的请求头、POST /api/login和空对象，返回400 application/json；厨房业务代码自身的Origin拒绝也返回JSON。因此推测是网站入口或安全防护规则拒绝了容器请求，具体来源仍需网页标识或平台日志证据，不能仅凭403认定地域限制、Cloudflare规则或网站必须登录。

本次Sites连接无法读取该项目配置，返回project not found；无法核对或修改平台访问配置。没有将现有共享厨房迁走，也没有尝试绕过浏览器验证。

沿用用户已确认的诊断方案，补充固定错误页类别、Cloudflare请求编号、固定响应服务名称及网页中的数字错误编号。不记录HTML正文、Cookie、口令、票据或任意响应头。15项离线检查通过，包括拒绝页识别及敏感内容不写入日志。标识识别只用于定位，不能视为拒绝规则已经修复。

部署该次提交后重新尝试登录，收集“错误页类别”“网站错误编号”“网站请求编号”；随后按官方权限或拒绝规则处理。官方403说明：https://developers.cloudflare.com/support/troubleshooting/http-status-codes/4xx-client-error/error-403/ 。

## 第三次云端证据：浏览器验证页

用户提供10月9日21:17:17的springboot-5wzu-004日志：POST /api/login，1038毫秒收到403 text/html，响应服务cloudflare，请求编号a47daa1fdd5df50e-LAX，识别为Cloudflare浏览器验证页。日志没有提供具体安全规则编号，因此仍不能确定触发验证的规则是IP信誉、自动请求识别、地域或其他条件。

Cloudflare官方说明指出，验证页会在请求到达目标页面前返回完整HTML，验证需要浏览器环境，可能需要JavaScript或人工交互。当前接入服务是Node HTTP客户端，不是用于完成浏览器验证的页面。原设计中“容器可稳定调用Sites业务接口”的前提在实际云端不成立。

优先的最小处理方式应是由网站平台提供受支持的服务调用授权，或由该域名安全规则管理方按正式规则配置接口访问。当前Sites工具无法读取该项目配置，不能自行调整Cloudflare规则，也不能承诺已有服务凭据可以解决此类验证。
